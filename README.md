# Asuna Math Tutor

Настольный репетитор по дифференциальным уравнениям и уравнениям математической физики. Загружаешь фотографии конспекта, PDF, DOCX или текст — Асуна разбирает их вместе с тобой, задаёт вопросы и ведёт параллельную тетрадь с формулами и планом повторения.

Приложение локальное: Electron-окно, локальный TTS-сервер и любой OpenAI-совместимый endpoint для моделей. Никаких внешних сервисов, кроме того адреса, который ты сам укажешь.

## Возможности

- фотографии, PDF, DOCX, TXT и Markdown как материалы занятия;
- режимы: диагностика знаний, объяснение темы, подготовка к экзамену, тренировка, тест с проверкой, разбор задачи, проверка твоего решения;
- тетрадь справа: формулы, текущий шаг, проверки и следующий вопрос;
- профиль между сессиями: цель, курс, пробелы, ошибки, освоенное, график повторения 1–3–7–14 дней;
- LaTeX через KaTeX, озвучка ответов локальным Silero;
- встроенная проверка зрения модели: приложение не даёт отправить фотографии модели, которая их не читает.

## Требования

- Arch Linux (скрипты рассчитаны на Arch + GNOME);
- `nodejs`, `npm`, `poppler` — ставит установщик;
- своя LLM-модель: Ollama, LM Studio, vLLM, OpenRouter, любой OpenAI-совместимый сервер.

Для фотографий нужна **vision-модель** — обычная текстовая их не прочитает.

## Установка

```bash
./install.sh
```

Дальше запуск:

```bash
asuna-math-tutor
```

или через GNOME → Applications → Asuna Math Tutor. Без установки: `npm install && ./run.sh`.

## Модель

По умолчанию `http://127.0.0.1:11434/v1` и `qwen2.5:32b`. Любой OpenAI-совместимый адрес подходит — Ollama, LM Studio, vLLM, OpenRouter.

Если основная Асуна уже настроена, приложение подхватывает её конфиг (`~/.config/Asuna VectorHeart/vectorheart-settings.json`), а изменения хранит отдельно.

## Фотографии: почему модель иногда «не видит» фото

Часть локальных шлюзов принимает картинку, тратит на неё токены, но наружу отдаёт модель без зрения. Ответ приходит уверенный и правдоподобный, хотя модель ничего не видела и выдумала ответ.

Поэтому перед отправкой приложение проверяет модель настоящей пробой: рисует картинку со случайными цифрами, отправляет её и сверяет ответ. Если модель цифры не назвала — отправка фото блокируется с объяснением, потому что лучше явная ошибка, чем выдуманный разбор твоего конспекта.

- статус зрения: панель **Модель** → «Проверить зрение модели»;
- ручная метка «считать, что модель читает фото» — для серверов, которые не проходят проверку;
- **Shift+Enter** — отправить сообщение без фотографий;
- в композере видно, сколько фото уходит в запросе и читает ли их модель.

Фото перед отправкой уменьшаются до 1280 px по большей стороне и сжимаются в JPEG (до 900 КБ): в исходном виде снимок с телефона весит мегабайты, и многие локальные шлюзы на таких запросах отвечают 502 или зависают.

## Аватар

Аватар Live2D — необязательный. Ресурсы движка и моделей в репозиторий **не входят**: если папки `resources/libs` и `resources/models` пусты, приложение работает как обычно, а в окне аватара горит «АВАТАР НЕ УСТАНОВЛЕН». Чтобы включить аватар, положи рядом с движком и моделями в нужную раскладку:

```
resources/libs/    pixi.min.js  live2d.min.js  cubism2.min.js
resources/models/  <id>/<id>.model.json  <id>/exp/  <id>/mtn/  <id>/moc/
resources/models_manifest.json
```

Персона (имя, тон, длина ответа, правила подсказок) лежит в `character.json` и подставляется в системный промпт — правь файл, а не код.

## Рядом с основной Асунной

```bash
./launch-with-asuna.sh
```

или `ASUNA_DIR=/path/to/asuna ./launch-with-asuna.sh`. Запускает обе программы; исходники Асунны не изменяются.

## Структура

```
src/            окно приложения: main.js (IPC, файлы, TTS), renderer.js (занятие), avatar.js
server/         tts_server.py — локальный Silero на 127.0.0.1:8009
character.json  персона: имя, голос, методика, формат ответа
resources/      аватар Live2D (в репозитории не хранится)
```

Профиль, сессия, настройки модели и профиль зрения лежат в `~/.config/asuna-math-tutor/tutor-data/`.
